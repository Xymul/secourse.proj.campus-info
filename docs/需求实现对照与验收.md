# 需求实现对照与验收自测

依据《此刻校园 软件需求规格说明书》第 7.1 节「验收标准」，逐项对照实现与自测结果。

| 验收项 | 验收要求 | 实现方式 | 自测结果 |
| --- | --- | --- | --- |
| 地图浏览 | 能加载校园地图并按分类展示信息节点；点击节点可查看详情 | OpenLayers + OSM 底图；`GET /api/posts/map` 按视野 bbox 加载；分类 chips 过滤；同地点聚合节点；点击弹窗 → 详情页 | ✅ 视野内返回节点，聚类节点显示「地点名（N 条信息）」，弹窗可跳详情 |
| 搜索 | 能进行关键词搜索；AI 搜索能处理典型自然语言校园需求并返回相关结果 | `GET /api/search/keyword`（LIKE 匹配）与 `GET /api/search/ai`（意图解析 + BM25 变体排序 + 匹配原因 + 条件放宽） | ✅ 「图书馆 丢的校园卡」正确识别 分类=失物招领、地点=图书馆，Top1 相关度 100% 并给出 4 条匹配原因；「附近1公里的二手台灯 预算300元」识别出 距离/预算/分类 |
| 发布 | 能创建帖子；能设置分类、地点和有效期；AI 辅助建议可被用户修改后提交 | `POST /api/posts` + `POST /api/ai/suggest`；发布页表单支持分类/地点/有效期/标签/联系方式，AI 建议自动回填且可修改 | ✅ 发布返回 `PUBLISHED`，有效期按分类默认值或自定义天数计算；AI 建议命中「失物招领」并建议 3 天有效期 |
| 互动 | 能评论；能进行信息验证/反馈；失物招领能形成认领流程 | 评论、点赞、证实/证伪（唯一约束 + 20s 冷却）、认领申请与发布者审批（通过后信息置为已解决） | ✅ 证实后可信度 100%；20 秒内重复验证被拒（提示「操作过于频繁」）；认领流程可用 |
| 治理 | 能举报信息；管理员能查看并处理举报/审核；过期信息能按规则自动处理 | `POST /api/posts/{id}/reports` → 阈值自动转待审核；后台审核动作 APPROVE/REJECT/REMOVE/RESTORE；`@Scheduled` 每日过期治理 + `POST /api/admin/tasks/expire` 手动触发 | ✅ 举报成功入库；重复举报被拒；过期任务执行并写入 `task_record` 与操作日志 |
| 后台 | 至少能完成分类、内容、用户、举报、地点等基础管理并记录关键操作 | 后端 `web/admin/*`、前端 `views/admin/*`；分类/地点/用户/举报/审核/任务/日志/分析全覆盖 | ✅ 仪表盘统计 1566 条信息（1131 已发布 / 100 待审核 / 232 已过期）、31 用户、90 地点、32 待处理举报、84 异常关注 |
| 多租户 | 校区切换后数据互不影响 | `school.is_test_data` + `sort_order`；华农 2 个正式校区置顶，江南/复旦/浙大标记为测试数据校区；模拟信息只写入测试校区 | ✅ 切换校区后信息数独立（测试校区 681 / 华农初始 0，发布后 1）；华农两校区各自动生成 18 个校园地点与 6 个账号 |
| 数据 | 核心业务数据能正确保存、查询、修改和关联，异常操作有明确提示 | JPA 实体 + 外键约束 + 事务；`GlobalExceptionHandler` 统一返回可读错误 | ✅ 单元 + 集成测试 10 项全部通过；异常场景（无效参数、越权、频繁操作）均返回明确中文提示 |
| 质量 | 关键功能在规定测试环境下通过功能测试；无阻断核心业务流程的严重缺陷 | `mvn test`（含端到端 MockMvc 流程）、PostgreSQL 实机冒烟 26 项 | ✅ 全部通过 |

## 需求规格说明书章节对应

| 需求章节 | 实现内容 |
| --- | --- |
| 3.1.1 F1 校园地图与信息浏览 | 地图展示、当前位置（浏览器定位）、分类筛选、信息节点、地点详情、同地点信息聚合 |
| 3.1.1 F2 信息搜索 | 普通关键词搜索、AI 智能搜索、意图解析、相关性匹配、结果解释（匹配原因 + 检索说明） |
| 3.1.1 F3 信息发布 | 标题/正文/图片输入、地点选择、分类、有效期、AI 辅助分类与建议、发布/编辑/下架/已解决 |
| 3.1.1 F4 互动与协同验证 | 评论、点赞、信息验证（证实/证伪/存疑）、失物招领认领、联系方式展示控制（脱敏） |
| 3.1.1 F5 信息治理 | 举报、敏感信息提醒、内容审核、过期自动处理、信息状态管理、操作日志 |
| 3.1.1 F6 后台运营管理 | 仪表盘、内容审核、用户管理、举报管理、地点核验、分类管理、任务记录、操作日志、数据分析 |
| 4 数据需求 | `docs/数据库设计说明.md`（13 张表，覆盖 User/Post/Category/Location/Comment/Verification/Report/OperationLog 等数据对象） |
| 5 性能需求 | 地图按视野加载避免全量；列表分页限制最大 100 条；检索候选集上限 1200 条；统计接口使用聚合查询 |
| 6.1 用户界面 | 首页 / 校园地图 / 搜索页 / 发布页 / 帖子详情页 / 管理后台（与需求表格一一对应） |
| 6.2 软件接口 | 地图：OpenLayers + OSM（可切换高德/腾讯瓦片）；AI：自实现算法（接口已封装，可替换为大模型）；存储：图片存 URL |
| 7.2 质量属性 | 权限控制（拦截器 + 角色）、隐私保护（联系方式脱敏）、规则配置化（`campus.*` 配置项）、日志留痕、异常可读提示 |
