校园信息地图(无AI版)开发步骤详解
校园信息地图（无AI版）开发步骤详解
第一步：产品原型与接口设计
目标：明确长什么样、怎么交互、数据怎么传。
使用软件：
Figma / Pixso：用于绘制UI原型（地图页、详情页、手动发布表单、验证进度条、管理后台大屏）。
Apifox / Postman：用于定义和调试前后端API接口（如获取附近帖子、证实/证伪接口）。
具体任务：

    梳理二手交易、失物招领等固定分类。
    设计带有 school_id 的多租户切换逻辑。
    产出所有页面的UI设计图，并定好前后端交互的数据格式。

第二步：数据库与环境搭建

目标：建立支持空间地理检索和全文搜索的底层架构。

使用软件：

    Docker Desktop：用于本地快速部署数据库环境。
    PostgreSQL + PostGIS 插件：主数据库，利用 PostGIS 存储经纬度并提供空间范围查询。
    Elasticsearch：用于替代AI语义的传统全文检索引擎。
    Redis：用于缓存高频地图点位和控制高并发下的证实/证伪防刷机制。

具体任务：

    用 Docker 跑起 PostgreSQL、Redis 和 Elasticsearch 容器。
    设计数据库表，核心信息表必须包含 school_id（多租户隔离）、lat（纬度）、lng（经度）、expire_time（过期时间）。

第三步：后端核心业务开发

目标：写接口，处理地图逻辑、搜索逻辑和系统定时任务。

使用软件：

    VS Code / Tree IDE / IntelliJ IDEA：写代码的开发工具。
    Git & GitHub/GitLab：代码版本控制。
    框架：Go (Gin) 或 Java (Spring Boot) 或 Python (FastAPI)。

具体任务：

    LBS接口开发：写一个接口，接收用户当前经纬度，通过 PostGIS 查询周边 X 公里内的有效帖子，返回给前端绘制地图。
    全文检索开发：将信息同步到 Elasticsearch，实现基于关键词、时间（新鲜度）、验证数的筛选和混合排序。
    协同验证机制：写"证实"和"证伪"接口，状态互斥，结合 Redis 限制单用户重复操作，并在证伪过多时触发后台预警。
    生命周期闭环：利用定时任务每天定时清理到达有效期的帖子，并在发布、审核、过期各环节用打上日志留痕。

第四步：客户端前端开发（地图展现）

目标：做出让用户在手机上点按、拖拽的地图界面。

使用软件：

    HBuilderX (Uni-app) 或 微信开发者工具：开发跨平台小程序。
    高德地图 小程序 SDK 或 腾讯地图 SDK：底图支持。

具体任务：

    接入地图 SDK，请求用户定位授权。
    调取后端 LBS 接口，将返回的信息以点位形式呈现在地图上，点击标记可查看详情。
    开发发布表单页，由于去掉了 AI，必须强制要求用户手动选择分类下拉框和有效期。
    在详情页开发验证机制，将"证实/证伪"结果以百分比直观展示。

第五步：后台管理端开发

目标：给管理员一个审核和看数据的界面。

使用软件：

    Vue 3 + Element Plus：后台前端框架。

具体任务：

    搭建登录和多角色权限。
    开发"内容审核列表"和系统管理员查看运营分析数据的界面。
    监控被高频证伪触发平台关注的帖子。

第六步：测试、模拟数据与部署

目标：验证产品并在服务器上线。

使用软件：

    JMeter：用于并发压力测试。
    Docker + Nginx：线上服务器容器化部署与反向代理。

具体任务：

    准备并导入1500余条包含江大、复旦、浙大的模拟校园数据。
    测试多租户验证，确保切换学校信息独立。
    将项目部署上线，跑通从第一行代码到最后一次部署的完整生命周期。
