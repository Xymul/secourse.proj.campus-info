# 数据库设计说明

数据库：PostgreSQL（验证版本 18）。表结构由 Flyway 管理：`backend/src/main/resources/db/migration/V1__init_schema.sql`。
Hibernate 设置为 `ddl-auto=validate`，启动时校验实体与表结构是否一致。

## 1. E-R 概览

```
school 1───n app_user
school 1───n campus_location
school 1───n post
category 1───n post
campus_location 1───n post
app_user 1───n post（作者）
post 1───n comment / verification / report / claim / post_like
app_user 1───n comment / verification / report / claim / post_like
app_user 1───n auth_token
operation_log（操作留痕，弱关联操作人）        task_record（定时任务执行记录）
```

## 2. 表结构摘要

| 表 | 关键字段 | 约束与索引 | 说明 |
| --- | --- | --- | --- |
| `school` | `code`(唯一)、`name`、`city`、`center_latitude/longitude`、`default_zoom`、`is_test_data`、`sort_order`、`status` | `code UNIQUE`、`idx_school_sort_order` | 多租户维度；`is_test_data` 区分正式校区与演示/测试数据校区，`sort_order` 控制前端下拉排序（正式校区置顶） |
| `app_user` | `username`(唯一)、`password_hash`、`nickname`、`role`、`status`、`credit_score`、`school_id` | `username UNIQUE`、`FK school` | 用户与角色（USER/ADMIN） |
| `category` | `code`(唯一)、`name`、`base_valid_days`、`sort_order`、`color`、`status` | `code UNIQUE` | 分类可后台配置，默认有效期驱动发布 |
| `campus_location` | `school_id`、`name`、`area`、`latitude/longitude`、`status` | `FK school`、`idx_location_school(school_id,name)` | 校园地点，支持核验状态 |
| `post` | `title`、`content`、`category_id`、`location_id`、`user_id`、`latitude/longitude`、`tags`、`ai_assisted`、`expire_at`、`status`、`verify_true/false_count`、`view/comment/like/report_count`、`hot_score`、`version` | 4 个 FK；`idx_post_school_status_expire`、`idx_post_bounds(school_id,latitude,longitude)`、`idx_post_hot_score` 等 | 信息节点主体；`version` 为乐观锁列 |
| `comment` | `post_id`、`user_id`、`content`、`status` | `FK`、`idx_comment_post` | 评论 |
| `verification` | `post_id`、`user_id`、`result`(TRUE/FALSE/UNKNOWN)、`remark` | `UNIQUE(post_id,user_id)`、`idx_verification_post` | 协同验证，唯一约束实现「状态互斥」 |
| `post_like` | `post_id`、`user_id` | `UNIQUE(post_id,user_id)` | 点赞 |
| `report` | `post_id`、`user_id`、`reason`、`detail`、`status`、`handled_by/at`、`handle_remark` | `idx_report_status(status,created_at DESC)` | 举报及处理 |
| `claim` | `post_id`、`user_id`、`description`、`contact`、`status`、`handled_by/at` | `idx_claim_post` | 失物招领认领 |
| `operation_log` | `operator_id`、`operator_name`、`action`、`target_type`、`target_id`、`detail`、`result` | `idx_log_created_at` | 关键动作留痕 |
| `task_record` | `task_name`、`task_type`、`status`、`affected_count`、`message`、`started_at/finished_at` | — | 定时任务轨迹（含失败记录） |
| `auth_token` | `token`(PK)、`user_id`、`issued_at`、`expires_at`、`last_access_at` | `FK user`、`idx_token_user` | 轻量登录令牌 |

## 3. 设计要点

1. **多租户隔离**：`post`、`campus_location`、`app_user` 均带 `school_id`，所有面向用户的查询默认按当前学校过滤；
   搜索候选集只加载当前学校数据，切换校区互不影响。
2. **正式校区与测试数据校区**（`school.is_test_data` + `sort_order`，见迁移 `V2__school_real_campus.sql`）：
   - 正式校区：**华中农业大学（狮子山主校区）**、**华中农业大学（襄阳校区）**，`is_test_data = false`、`sort_order = 1/2`，置顶展示；
   - 测试数据校区：江南大学、复旦大学、浙江大学，`is_test_data = true`、`sort_order = 10/11/12`，前端显示「测试数据」标记；
   - **模拟信息只写入测试数据校区**（`MockPostGenerator` 按 `is_test_data` 过滤并按校区均分），正式校区由真实用户发布内容；
   - 校区地区坐标取自 OSM/Photon 地理编码（WGS-84），校园内地名（图书馆、食堂等）由 `DataSeeder` 按模板生成 18 个，
     可在后台「地点核验」中改名与调整坐标。
3. **信息生命周期**：`post.status` 取值 `PENDING / PUBLISHED / REJECTED / REMOVED / EXPIRED / RESOLVED`；
   `expire_at` 由分类默认有效期或用户自定义天数计算；定时任务把到期的 `PUBLISHED/PENDING` 置为 `EXPIRED`。
4. **协同验证一致性**：`verification` 唯一约束 + `post.version` 乐观锁 + 计数冗余字段（`verify_true_count`/`verify_false_count`），
   既保证「一人一票」，又保证列表页无需聚合查询。
5. **热度与可信度**：`hot_score` 由互动与验证结果计算并持久化，供「热门排序」与后台预警使用。
6. **空间检索**：
   - 默认方案（无需扩展）：`latitude/longitude` 使用 `double precision`，在 SQL 中以 Haversine 公式计算距离，
     `(school_id, latitude, longitude)` 组合索引辅助矩形范围预筛；
   - 可选方案（`db/optional_postgis.sql`）：新增 `geography(Point,4326)` 列 + GIST 索引 + 触发器自动同步，
     并可改用 `ST_DWithin` / `ST_Distance` 获得更好的大规模性能。
7. **审计与可追溯**：所有关键写操作（发布、编辑、审核、下架、举报、认领、用户状态、地点核验、过期治理）
   都会写入 `operation_log`，日志与业务操作处于同一事务，保证「日志即事实」。
8. **迁移不可变原则**：`V1__init_schema.sql`、`V2__school_real_campus.sql` 已在库中执行，
   其内容不可再修改（否则 Flyway 校验和失配导致启动失败）；后续结构变更请新增 `V3__xxx.sql`。
